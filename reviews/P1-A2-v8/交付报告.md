## 二、实现结构

### 2.1 四阶段

```
阶段 A：CODE = 围栏 ∪ 行内代码（围栏按行识别，行内代码不跨行，`\`` 不算闭合）
阶段 B：在 CODE 外扫描 DSML 标记 + 白名单普通 XML 标签，生成 SYNTAX 区间
阶段 C：按段落配对引号；两端都在同一 SYNTAX 内的引号不产生 QUOTE
阶段 D：保护区 = CODE ∪ QUOTE；主循环先查保护区，再走 R1/R2/R3
```

普通 XML 也进 SYNTAX 是施工中补上的：否则 `name="x"` 的属性引号会被当成 QUOTE，把整段普通 XML 结构保护起来，
导致 `<invoke>…</invoke>` 不再清理。这一条是旧测试大面积失败时定位到的。

### 2.2 R1 七状态

| 状态 | 行为 |
|---|---|
| `COMPLETE` | 栈完整配对 → 整段删；若与保护区相交 → 整体跳过（R1-f），不回流 R2/R3 |
| `UNCLOSED_SINGLE` | 只有外层起始、没有内层嵌套 → 只删起始标签（R1-c/C1） |
| `CROSS_PARAGRAPH` | 外层跨空行 → 视为不完整，只删外层起始标签（R1-e/E1） |
| `ORPHAN_CLOSE` | 栈空时遇到双竖线闭合 → 保留（R1-d/D1） |
| `ORPHAN_CLOSE_SINGLE` | 单竖线闭合 → 整体保留，不残留 `</` |
| `MISMATCH` | 栈非空、闭合与栈顶不同名 → 不删（R1-a/A3） |
| `NESTED_UNCLOSED` | 内层完整但外层未闭合 / 顺序错乱 → 不删（R1-b/B1） |
| `ATTR_UNTERMINATED` | 起始标签属性未闭合或无 `>` → 不删到文本末尾（R1-h/H1） |

`UNCLOSED_SINGLE` 与 `NESTED_UNCLOSED` 用「扫描过程中栈的最大深度」区分：深度一直为 1 才算 C1，出现过内层标签就按严格栈式的不猜测处理。

### 2.3 R2/R3 与 attrs

- R2-A：标记后是白名单标签且有 `>` → 删到 `>`（含），`>` 后原样。
- R2-B：属性未闭合 / 没有 `>` → **只删标记和标签名，两者之间的空白保留**。这条是新增测试第 4、13 条抓出来的：
  最初把「标记 + 中间空白 + 标签名」当成一个连续区间删，少了规范要求的那个空格。
- R3：标记后不是完整白名单标签 → 只删标记，其余空白原样。
- `_scan_attrs` 三状态各有测试；属性值内 `>` 不参与结束符判断；普通撇号不开启属性值。

### 2.4 额外兼容：`</<` 叠加残片

线上出现过 `</<｜｜DSML｜｜ invoke>`（模型把 `</` 和 `<｜｜DSML｜｜` 打了两次）。
v7 五形态不覆盖它。按 D1「孤立闭合标签保留」的精神，把 `</` 后的 `<` 并进闭合标签整体保留，
避免删掉内部标记后只剩一个孤零零的 `</`。这是规范外的一处小扩展，复审时请确认是否接受。

## 五、复审重点：v7 严格栈式与线上实际泄漏形态的冲突

**现象**：P1-A1 的 LEAK 用例（线上实测的泄漏形态）在新实现下**整段原样保留**：

```
<｜｜DSML｜｜ calls>
<｜｜DSML｜｜ invoke name="reveal_time">
<｜｜DSML｜｜ parameter name="x">1</｜｜DSML｜｜ parameter>
</｜｜DSML｜｜ invoke>
<｜｜DSML｜｜ /calls>
```

`calls` 的闭合写成了 `<｜｜DSML｜｜ /calls>`——标记 + ` /calls>`，不是 `<` + `/` + 双竖线。
v7 的五形态里没有这一种，所以它被当作 R3 的裸标记；外层 `calls` 因此"有起无闭"，
但内层 `invoke/parameter` 是完整的，按 R1-b「嵌套未闭合 → 不猜测、不删」整段保留。

DSML 包裹的 `propose_change` 提案（闭合全部写成 `<｜｜DSML｜｜ /parameter>`）同理：
提案能入箱，但正文清洗后原样，标记会跟着消息发出去。

**这不是实现 bug**，是 v7「严格栈式配对、异常不猜测」的直接结果。P1-A2 对完整双竖线配对、
孤立起始标签、裸标记 R2/R3 是有效的（规范 31 条里 1、2、3、5、24、26、29、30、31 都删干净了）。

**需要主人裁定**：

1. 接受 v7 的保守行为（LEAK 原样保留，靠提示词/后续规则处理）；
2. 把「标记 + ` /name>`」补进 v7 的闭合形态（第六种形态），实现按闭合处理，再跑一遍测试；
3. 或者只在这种畸形结构上降级为「逐标记 R3 清理」（删掉所有 `｜｜DSML｜｜`，接受 `/calls>` 等残片）。

我没有擅自动规范。当前代码严格按 v7；如果选 2 或 3，改动量不大，但需要先把规范补一条。
