## 二、修复

### 2.1 `_candidate_regions()` 跳过 QUOTE 与外层 SYNTAX

v11 只跳过了 CODE，引号内和属性值里的伪候选会被误识别为独立候选，可能把隔离区间扩到正文。

v12 的签名改为：

```python
_candidate_regions(text, code_regions, quote_regions, syntax_regions)
```

- 扫描时跳过 `CODE ∪ QUOTE`；
- 候选标记如果落在某个外层 SYNTAX 区间内（`s < pos < e`），
  说明它在合法标签的属性值里，不算独立候选。

调用处：`isolated = _candidate_regions(t, code, quotes, syntax)`。

### 2.2 `_syntax_regions()` 只生成合法语法区间

v11 对所有标记都生成 SYNTAX；没有 `>` 的非法候选会生成 `(start, 文本末尾)` 的区间，
导致后面的引号全部被排除在 QUOTE 之外。

v12 改为：

- 标准起始标签：`_match_tag()` 匹配白名单标签才生成；`FOUND_END` 到 `>` 前，
  `UNTERMINATED_ATTRIBUTE` 到末尾（属性未闭合时保护）；
- 合法第二种闭合：生成到 `>` 前；
- 异常闭合（`_match_close_tag()` 返回 None）：不生成；
- 非法候选、裸标记、非标签标记：不生成。

### 2.3 新增回归（`二十二` 组，5 项）

| 场景 | 输入 | 期望 |
|---|---|---|
| 引用内候选（无 `>`）+ 后续合法结构 | `「<｜｜DSML｜｜ /bad」后面 <calls>正文</calls>` | `「<｜｜DSML｜｜ /bad」后面 ` |
| 引用内候选（有 `>`）+ 后续普通 XML | `「<｜｜DSML｜｜ /bad>」后面 <invoke>X</invoke>` | `「<｜｜DSML｜｜ /bad>」后面 ` |
| 属性内伪候选（完整结构） | `<calls name="<｜｜DSML｜｜ /bad>">正文</calls>` | `""` |
| 属性内伪候选（无闭合） | `<calls name="<｜｜DSML｜｜ /bad>">正文` | `正文` |
| 引用 + 后续合法结构精确 | `前缀「<｜｜DSML｜｜ /bad」中段 <calls>正文</calls> 结尾` | `前缀「<｜｜DSML｜｜ /bad」中段  结尾` |

前两条验证引用内容逐字保留、后续结构正常清理；第三、四条验证属性值和属性外的正文；
第五条同时验证引用内容和后续合法结构。
