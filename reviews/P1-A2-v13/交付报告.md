## 二、修复

### 2.1 问题

v12 的 `_syntax_regions()` 第二遍扫描普通 XML 时用的是：

```python
gt = text.find(">", start)
```

如果普通 XML 起始标签的属性值里含 `>`（例如 `name="a>b"` 或
`name='x><｜｜DSML｜｜ /bad>'`），`find` 会停在属性值内的 `>`，SYNTAX 区间被截断：

- 双引号属性对会变成「开引号在 SYNTAX 内、闭引号在 SYNTAX 外」→ 误产生 QUOTE；
  QUOTE 与普通 XML 的删除区间相交 → 起始标签不被删，只剩 `</invoke>` 被当孤立闭合删掉；
- 单引号属性值里的伪候选落在截断区间之外 → 被 `_candidate_regions()` 误识别为独立候选，
  隔离区间把普通 XML 的删除挡住。

v12 实测：`<invoke name="a>b">INNER</invoke>` → `<invoke name="a>b">INNER`；
`<invoke name='x><｜｜DSML｜｜ /bad>'>INNER</invoke>` → `<invoke name='x><｜｜DSML｜｜ /bad>'>INNER`。
两种都残留起始标签、INNER 未随普通 XML 一起清理。

### 2.2 修法

普通 XML 起始标签改用引号感知的 `_scan_attrs(text, x.end())`：

```python
st, gt = _scan_attrs(text, x.end())
end = gt if st == "FOUND_END" else n
out.append((start, end))
```

闭合标签没有属性，用 `_XML_CLOSE` 匹配末尾：`out.append((start, c.end() - 1))`。

### 2.3 效果

6 个新增案例现在都清理为 `""`；INNER 随普通 XML 一起删除，属性值里的伪候选不再误隔离。
